# Plan 06 — Trust register

**Gate:** every register entry names a falsifier; the entry count is enforced by
a CI ceiling script in the shape of `scripts/check_mt_cfg_ceiling.sh`; and
`check_doc_drift.sh` verifies that every predicate marked *assumed* in the
invariant registry has a matching register entry.

**Status:** not started. Depends on plans 01 and 02.

## Goal

Some premises cannot be established — only isolated and monitored. The register
is the single place they live, and the ceiling is what stops the list from
growing quietly. This is the one mechanism worth transplanting from the
terminated proof track, where it existed as a `TrustGrant` type generated by a
build script from a `TRUSTED.toml`. Here it is a markdown table and a counting
script, which is the right size for the job.

## Why a register rather than trusting the comments

The study identified the sociological failure mode precisely: `trust` is the
path of least resistance, and a registry that grows monotonically converts a
proof layer back into prose with extra steps. The same applies to a comment
corpus. Two properties defeat it:

1. **Every entry names its cheapest falsifier** — a Miri mode, a fuzz target, a
   `loom` model, a differential fixture. An assumption nobody can even attempt
   to break is not an assumption, it is a hope; writing the falsifier column
   forces the distinction at registration time rather than by convention.
2. **The count is ceilinged in CI.** Adding an entry is a deliberate act that
   requires raising a number in a script, which shows up in review.

The study's own registry reader failed open — it matched constructor names as
substrings of the raw file, so a commented-out entry granted trust. A markdown
table counted by `grep -c` on a row marker has no such failure mode, which is a
fair illustration of why the simpler mechanism is also the safer one here.

## Contents

New `docs/TRUST_REGISTER.md`. One row per entry:

| Field | Meaning |
| --- | --- |
| ID | Stable identifier, cited from `// SAFETY:` comments |
| Predicate | The invariant-registry predicate this assumption discharges |
| Class | `spec-licensed-ub` \| `ffi-abi` \| `deviation` \| `upstream` \| `residual` |
| Statement | What is being assumed, in one sentence |
| Why unprovable | The reason it cannot be established here |
| Falsifier | The cheapest known way to detect it being false |
| Invalidated by | What future change would break it |

## Known entries at authoring time

Seeded from the study and from plan 04, Part C:

**Class `spec-licensed-ub`** — ECMA-335 itself declares behavior undefined when
unverifiable IL supplies invalid operands. `cpblk`, `initblk`, `Unsafe.*`.
Formally these are conditional: *if* the input IL is verifiable in the
`III.1.8` sense, or the host accepts the unverifiable-code trust boundary,
*then* the implementation is safe. Falsifier: `fuzz_executor` on malformed IL.
Not closable without a mechanized CIL verifier for the executed fragment.

**Class `ffi-abi`** — P/Invoke ABI agreement between a libffi CIF and an
arbitrary native library is not provable in any model that stops at the process
boundary. One entry per imported function shape, not per function. The pinning
and liveness obligations *around* the call are F1 and are not part of this
entry. Falsifier: the P/Invoke integration fixtures.

**Class `deviation`** — the standard says one thing, `dotnet-rs` does another,
deliberately:
- **Non-moving GC.** Correct today; invalidated the day a compacting collector
  lands. A great deal of F1 reasoning depends on it *silently*, which is exactly
  why it needs an entry with a filled-in "Invalidated by" column.
- **Single load context.**
- **Stop-the-world-only collection.**
- **The intentional alignment divergence** already recorded in
  `diff_harness.rs`'s rejected-candidate list.
- **Unhandled-exception exit codes** (real .NET exits 134, `dotnet-rs` exits 1).

**Class `upstream`** — the `TypeIndex` transmute into `dotnetdll`'s private
layout. This one should be *fixed*, not trusted: a `#[repr(transparent)]`
guarantee or a public constructor upstream, in a crate the author owns. It gets
a register entry only until that lands, with "Invalidated by" reading *any
dotnetdll layout change*. Treat a long-lived `upstream` entry as a defect in the
register, not a fact about the world.

**Class `residual`** — assumptions surviving plan 08. Expect
`Transient(Box<Object>)` origins, which have no stable serializable handle by
construction, and the `UnmanagedPtr`/P-Invoke path where reconstructing a
pointer from an integer *is* the semantics of the operation.

## Steps

1. Write the table with the entries above, leaving the falsifier column blank
   where no falsifier exists yet.
2. **Any row with a blank falsifier is a work item for plan 02**, not a
   permanent state. Resolve or document each before the gate is claimed.
3. Add `scripts/check_trust_register.sh`: count rows, compare against a
   `CEILING` constant, print the count, exit 1 on excess. Mirror
   `check_mt_cfg_ceiling.sh` exactly — same structure, same output shape, so it
   reads as a sibling.
4. Wire the ID citation into `check_doc_drift.sh`: an ID cited in source must
   exist in the register, and a predicate marked *assumed* in the invariant
   registry must have a register entry.
5. Add the script to `check.sh --full` and to `ci.yml`.

## Not in scope

- Any Rust type, macro, or build-script mechanism for trust grants. The
  terminated study built one; it is archived. A table and a counter are
  sufficient and cannot fail open.
- Ranking or scoring entries by severity. Class plus falsifier is enough
  structure; a severity column invites arguing about numbers instead of removing
  entries.
