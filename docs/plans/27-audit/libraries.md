# Library test audit

Baseline `8431c1ab`. Scope: workspace crates other than dotnet-vm, dotnet-cli and dotnet-benchmarks, plus dotnet-value fuzz. [Source discovery](libraries-inventory.md) is an inventory, not a review. Inspection evidence below is not an execution result. No library tests or fuzz campaigns were run for this document. The source inventory and family inspection cover this partition; the production-policy decision in LIB-6 is a separate investigation.

## Findings

Suggested order: safety and false confidence first (LIB-1, LIB-2, LIB-3, LIB-6, LIB-7, LIB-9, LIB-11, LIB-15, LIB-16, LIB-18, LIB-20, LIB-22, LIB-25); then execution and fixture reliability (LIB-10, LIB-14, LIB-21, LIB-23); then contract tolerance and consolidation (LIB-4, LIB-5, LIB-8, LIB-12, LIB-13, LIB-17, LIB-19, LIB-24). LIB-6 requires a separate production-policy decision.

### LIB-1: Source guard is broader and weaker than its claimed path

**Rewrite** `dotnet_utils::gc::cross_arena::tests::arena_lifetime_transport`. The intended F1/F6 guarantee is that cross-arena tracing and harvest retain a live allocation pointer and identity through transport. This scans entire production files for two spellings and one exact `Vec` spelling, skipping comments and any line containing `register_object_ptr`. It can reject an unrelated legitimate exposed-provenance boundary in those files and can miss equivalent casts, helper calls or an integer buffer expressed with another type. The `dotnet_value` permissive and strict-core `arena_lifetime_transport` controls actually trace a `CrossArena` origin and harvest an object under an exact-identity lease; they exercise this transport sequence, not the VM coordinator. Retain these behavioral/Miri controls and exercise the production coordinator path where practical; replace the source scan with a path-specific structural guard only if an enforceable structural rule remains necessary. Verify `cargo test -p dotnet-utils arena_lifetime_transport` and the strict-core Miri selector and flags in `docs/CI.md`.

### LIB-2: Pointer arithmetic fuzz oracle does not prove provenance

**Rewrite claim / strengthen** `fuzz_managed_ptr_offset`. It invokes production `ManagedPtr::offset` on live local unmanaged, static and frame-home origins, independently computes in-bounds offsets and checks origin, byte offset and numeric address. However `.addr()` equality cannot establish provenance: a reconstructed pointer with identical address bits passes, despite the assertion message. Add a valid in-bounds access through the returned pointer under strict-provenance Miri in a deterministic test (the existing pointer arithmetic Miri tests may be extended); retain fuzz for numeric arithmetic and origin. Verify `cargo test -p dotnet-value ptr_arith` and the relevant Miri selector from `docs/CI.md`, and replay the target through `scripts/replay_fuzz_corpus.py`.

### LIB-3: Generated filter shape does not establish matching behavior

**Rewrite** `dotnet_macros::tests::{intrinsic_filter_checks_only_primitive_parameter_shapes,intrinsic_filter_is_true_only_when_all_parameters_are_non_primitive_shapes,intrinsic_filter_checks_every_normalized_primitive_keyword}`. The contract is that generated intrinsic overload filters distinguish supported primitive argument shapes and defer non-primitive matching to the handler. These call the production generator but check only statement counts and a final `true` literal. A generated block that rejects every argument, checks the wrong primitive, or does nothing still passes. Compile and execute generated filters against matching and mismatching signatures for the listed keywords and mixed shapes; retain a structural assertion only for a separately justified generator interface. Verify `cargo test -p dotnet-macros` and a relevant VM intrinsic dispatch integration test.

### LIB-4: Slot census enforces an arbitrary total rather than stable identities

**Rewrite** `dotnet_assemblies::support_contract_tests::{test_registry_slot_count,generated_slot_descriptors_preserve_stable_ids_and_exact_shapes,loaded_support_metadata_has_an_independent_literal_slot_census}` `dotnet_build_tools::support_slots::tests::parses_committed_twenty_one_slot_contract`, and `dotnet_assemblies::support_contract_validation_tests::{generated_runtime_slot_ids_are_required,unknown_id_is_a_contextual_contract_violation}`. `support_slots.def` is authoritative and the documented ABI requires existing IDs never be renumbered, a dense schema and exactly one metadata field per required ID. Literal `21` prevents an otherwise valid appended slot and requires coordinated count updates, while the census alone cannot detect replacing one ID with another. Preserve an independent named ID-to-number baseline to catch deletion/renumbering, compare metadata and registry IDs to the authoritative required set, retain duplicate detection and explicit shape/owner validation. Use an actually unknown out-of-range ID for malformed-ID cases rather than assuming 22 remains unknown, and reconsider `from_i32(22) == None` when a slot is appended. Verify `cargo test -p dotnet-assemblies support_contract` with real built support assembly, and `cargo run -p xtask -- verify-slots`; `DOTNET_SKIP_BUILD` supplies a stub and cannot validate the loader.

### LIB-5: Exact validation prose overconstrains diagnostic formatting

**Rewrite** `dotnet_assemblies::support_contract_validation_tests::{unknown_id_is_a_contextual_contract_violation,missing_id_reports_its_exact_expected_slot,duplicate_annotations_report_the_id_and_both_locations,misplaced_id_reports_actual_and_expected_locations,exact_signature_mismatch_reports_expected_and_found_shape,wrong_staticness_reports_actual_and_expected_staticness,runtime_slot_field_without_used_implicitly_is_a_contract_violation}`. Synthetic metadata reaches the production validator, and rejection plus ID, field and relevant actual/expected information is meaningful; full-string equality additionally rejects harmless punctuation and wording changes. Assert the error variant, structured owner/field, and meaningful diagnostic components while keeping distinct malformed metadata cases. Verify `cargo test -p dotnet-assemblies support_contract_validation_tests` against the real embedded support assembly.

### LIB-6: Equal resolution errors treated as type identity

**Rewrite after production decision** `dotnet_types::comparer::tests::concrete_types_equal_keeps_equal_error_result_behavior`: the test constructs distinct user-type definitions and a resolver returning the same `TypeNotFound` for each, then requires production `concrete_types_equal` to return true. The asserted basis is explicitly legacy behavior; no independent compatibility or CLI requirement was found. Production `AssemblyLoader::locate_type` can return the same payload-free `SynchronizedValueType` for distinct value-type definitions with synchronized methods, so equal errors are possible with invalid metadata rather than only the mock. `is_assignable_to_impl` accepts concrete equality first and `dotnet_vm_ops::array_assignability` uses it, so unresolved distinct types could be accepted as equal or assignable if such inputs reach these paths. This is an inspection hypothesis, not a demonstrated guest-visible defect. The test certifies legacy equal-error behavior without a justified contract; propose conservatively treating resolution failure as non-equality (or propagating an error where the API permits). Investigate guest reachability and choose the production policy separately, then replace the regression with a test for that decision; preserve valid equality and resolution-error coverage. Verify `cargo test -p dotnet-types concrete_types_equal` and a focused VM array/type assignability regression after deciding the contract. A production issue, if confirmed, requires a separate tracked destination, not silent test removal.

### LIB-7: Retired variant scan can silently skip directories

**Rewrite** `dotnet_value::stack_value_cross_arena_retired::{stack_value_cross_arena_object_ref_stays_retired,scanner_distinguishes_origin_from_retired_stack_variant}`. A `StackValue` variant carrying only an arena ID would omit the generation/lease required by F1; the scan is explicitly source-policy evidence, and the scanner unit tests characterize expected spelling. `rust_files` returns on any failed `read_dir` and flattens failed entries, so even with >100 files and the `stack_value.rs` presence check it can silently omit an entire subtree. It also misses renamed or differently qualified equivalent representations. Fail on traversal errors and derive the file inventory from tracked workspace sources (or explicitly verify all intended roots), retaining the named target and scanner controls; use behavioral ABA/lease tests to establish runtime safety. Verify `cargo test -p dotnet-value --test stack_value_cross_arena_retired` in both feature configurations.

### LIB-8: Layout snapshots conflate representation and footprint

**Classify and revise where justified** both `dotnet_value` and `dotnet_vm_data` `layout_sizes_match_expected` integration tests and their compile-time assertions. Exact 64-bit snapshots catch changes to hot values and frames; `StackValue` movement cost has a documented performance motivation. Exact equality also rejects a smaller representation, and the runtime checks repeat the compile-time predicate; source comments alone do not establish which other exact sizes are ABI or safety constraints. Retain exact representation requirements and any justified footprint guards. Where a size is only a maximum performance budget, consider an upper bound; remove duplicate runtime checks only after confirming compile coverage across supported feature configurations. Verify `cargo test -p dotnet-value --test layout_sizes` and `cargo test -p dotnet-vm-data --test layout_sizes` with no features, multithreading and validation configurations.

### LIB-9: Error construction tests do not exercise the conversion

**Remove or replace** `dotnet_runtime_memory::access::tests::{compare_exchange_error_variants,check_bounds_error_promoted_to_compare_exchange_error}`. The contract is that compare-exchange reports mismatches and memory failures through the corresponding `CompareExchangeError` variant. The first constructs and destructures the same enum values, and the second applies `.map_err(CompareExchangeError::Bounds)` in the test rather than calling production compare-exchange. A broken production conversion still passes both. Replace with a real `RawMemoryAccess::compare_exchange_atomic` mismatch and out-of-bounds call asserting returned payload and unchanged storage; retain existing retired-owner and unaligned production-path controls. Verify `cargo test -p dotnet-runtime-memory access::tests` with both feature configurations.

### LIB-10: Version tests share fixed temporary paths

**Rewrite setup** `dotnet_assemblies::version_tests::tests::{test_version_binding_basic,test_binding_redirect}`. They exercise production version binding/redirects with named registered assemblies, but delete and recreate fixed global temp directories. Concurrent invocations can remove each other's fixtures or read partial redirects, causing a spurious result. Give each test an isolated temporary directory with cleanup; retain both match/mismatch and redirect assertions. Verify `cargo test -p dotnet-assemblies version_tests` and repeat concurrently with a second invocation.

### LIB-11: Cyclic constraint tests accept unrelated failures

**Rewrite** `dotnet_types::generics::constraint_cycle_tests::{test_direct_type_generic_self_reference_does_not_recurse,test_cyclic_generic_constraint_causes_unbounded_recursion_regression,test_cyclic_generic_constraint_detection_terminates_quickly}`. Termination of recursive generic constraint validation is a real requirement, and the call-limited resolver prevents runaway recursion. The direct case discards `result`; both cyclic cases merely exclude one error message and bound mock calls, so a different immediate error can pass. They duplicate the same scenario with different resolver caps. Use independently valid and invalid cyclic fixtures, assert the intended result and retain a bounded termination guard; merge redundant cases only if both failure modes remain covered. Verify `cargo test -p dotnet-types cyclic_generic_constraint` and `cargo test -p dotnet-types direct_type_generic`.

### LIB-12: Unequal hash values are not a correctness requirement

**Rewrite** `dotnet_types::members::method_description_eq_hash_tests::method_descriptions_with_different_parents_produce_different_hashes`. The contract is distinct declaring types must not alias cache entries; equal keys must hash equally, but unequal keys may collide. The production hash is tested with `DefaultHasher` and `assert_ne!`, which can fail for a valid hash function or collision. Retain the separate inequality test, and insert both descriptors into a map with a deliberately colliding hasher and verify independent retrieval; retain equality/hash consistency for equal descriptors. Verify `cargo test -p dotnet-types method_descriptions_with_different_parents`.

### LIB-13: Well-known enum count prevents legitimate extension

**Rewrite** `dotnet_types::wkt::tests::span1_is_appended_without_renumbering_existing_variants`. The explicit existing discriminants protect the cache indexing convention, but `WellKnown::COUNT == 60` rejects appending a new value. Preserve the old discriminant assertions and contiguous uniqueness/inventory check in `names_round_trip_and_discriminants_are_contiguous`, whose array length tracks `COUNT`, while allowing new names to be added. Verify `cargo test -p dotnet-types wkt::tests`.

### LIB-14: Atomic validation controls can pass without the intended path

**Rewrite** `dotnet_utils::atomic::tests::{test_validate_alignment_rejects_misaligned_pointer,test_load_field_misaligned_falls_back_in_mt,test_load_field_misaligned_falls_back_non_mt,test_mixed_access_validation,test_sizes}`. A `[u8; N]` has alignment 1, so adding one does not guarantee a misaligned address: the expected-panic case can fail for valid placement, and fallback cases can run the aligned path. Use explicitly aligned backing and offset one. `test_mixed_access_validation` calls the validator but never observes its warning, so removing warning emission passes; capture a structured diagnostic or narrow the claim. `test_sizes` interprets byte offsets using little-endian shifts without target-endian gating; compare native-endian bytes or gate the independent little-endian expectations. Retain width/order and valid-storage checks. Verify `cargo test -p dotnet-utils atomic::tests` with no features, multithreading and memory-validation.

### LIB-15: Sealed FieldType compile-fail reason is not verified

**Strengthen** `dotnet_value::layout::FieldType` compile-fail doctests. F2 requires unsafe decoding and sealed implementations; the examples request rejection of safe `read_from` and external implementation. A temporary minimal rustdoc probe run by the audit coordinator on pinned stable 1.95 passed `compile_fail,E0133` with an unrelated unresolved-name E0425 error and failed when the code compiled. Thus the annotation does not independently check the intended diagnostic in this toolchain. Add positive controls and check that these examples fail for the intended unsafe-call and sealed-supertrait reasons, as the VM effects diagnostic script does. Verify `cargo test -p dotnet-value --doc` and the diagnostic checker in both relevant feature configurations.

### LIB-16: Cross-arena race controls can pass without reaching their checkpoint

**Rewrite** `dotnet_utils::gc::cross_arena::lease_tests::{unregister_waits_for_outstanding_lease,record_and_harvest_race_with_reregistration,stress_stw_flag_transitions_with_lease_acquisition}`. Sleeping 20 ms does not prove the unregister worker entered teardown, so a worker scheduled only after lease release passes. The harvest test conditionally checks a new lease and passes if acquisition incorrectly returns `None`; the stress test discards both STW observations and its before/after generations despite claiming to verify them. Synchronize on a bounded teardown checkpoint, require the expected new lease, and coordinate flag/generation observations before comparing them; retain production registry calls and release/join on failure. Verify `cargo test -p dotnet-utils cross_arena` under both relevant feature configurations. Existing `arena_identity_registry_drain_reuse_control` already provides a stronger production close-and-drain checkpoint.

### LIB-17: Valid pointer offset result is discarded

**Remove or strengthen** `dotnet_value::pointer::tests::test_managed_ptr_offset_valid`. Its contract is that an in-range pointer offset produces the correct address/origin, but the returned pointer is discarded and no result is checked: a no-op offset passes. Assert the resulting offset and an in-range read, or rely on the distinct `ptr_arith` and retained range cases after confirming they cover the intended origin. Verify `cargo test -p dotnet-value test_managed_ptr_offset_valid` and relevant pointer arithmetic/Miri selectors.

### LIB-18: Multithreaded validation test has an empty body

**Rewrite gating** `dotnet_value::validation_tests::tests::test_arena_mismatch_panics`. The single-threaded validation leg checks wrong-arena access panics, but with `multithreading,memory-validation` the entire test body is `{}` and the runner reports a pass without checking anything. Gate the item to its actual configuration or implement an independent multithreaded mismatch assertion consistent with that feature's access policy; retain the separate dangling and STW tests. Verify `cargo test -p dotnet-value test_arena_mismatch_panics --no-default-features --features memory-validation` and the multithreaded validation leg; require discovery to reflect the gate.

### LIB-19: Publication model is duplicated and does not exercise VM publication

**Merge or relabel** `dotnet_value::object_tests::tests::{publication_old_path_diagnostic,publication_root_barrier_control,publication_pending_survival}`. The model demonstrates the gc-arena root write-barrier requirement with its own raw-slot `Collect` implementation, not the production VM `MarkObjects` path. The latter two call the identical `publication_drops(true)` fixture and assert exactly the same result; keep one positive and the negative control as model evidence, and retain separate production-path lifecycle tests. Verify `cargo test -p dotnet-value publication_` and the relevant VM collection controls.

### LIB-20: Tracing counter is not a collection-liveness test

**Relabel or strengthen** `dotnet_value::object::types::vector_object_ref_tests::tracing_a_value_type_vector_keeps_embedded_object_refs_alive`. It calls production `Vector::trace` with `CountingTrace` and asserts one trace call; no GC cycle or post-collection weak reference is observed. This catches a skipped trace but cannot establish the stated liveness guarantee. Preserve the trace assertion and rename its claim, or add a rooted vector plus weak witness across a real collection. Verify `cargo test -p dotnet-value tracing_a_value_type_vector` and run the added lifecycle control under Miri if changed.

### LIB-21: Concurrent object-codec fixtures reuse live arena IDs

**Rewrite setup** `dotnet_value::object_tests::tests::{codec_id40000,codec_registered_boundaries}` and the `with_test_gc_context`/`next_test_arena_id` helpers. Both codec tests independently register ID 40000, and the boundary test registers ID 1 while the helper starts its counter at 1. Parallel tests in the same process can therefore attempt duplicate live registrations and fail, or interact with one another. Serialize only fixed-boundary registration tests against all other users of those IDs, or allocate disjoint ID ranges and reserve the required boundary IDs across the test harness; retain the actual boundary cases. Verify repeatedly with `cargo test -p dotnet-value --features multithreading` at normal parallelism.

### LIB-22: Unmanaged fuzz roundtrip never checks the input address

**Strengthen** `fuzz_managed_ptr_roundtrip`'s `RoundtripInput::Unmanaged` case. The contract is preservation of unmanaged address bits through serialization. It checks tag and checksum, but skips both offset and resolved-address checks for this origin, so a writer/reader consistently producing zero can pass for every generated address. Assert the decoded unmanaged address and offset against the input, including null and high-bit values; retain the independently constructed unknown-subtag and other origin checks. The deterministic `test_managed_ptr_serialization_roundtrip` covers one unmanaged literal, but does not replace fuzzed addresses. Verify the target with `scripts/replay_fuzz_corpus.py` and a short fuzz run per `docs/FUZZING.md`.

### LIB-23: Corrupt-magic test runs when validation is compiled out

**Fix gating** `dotnet_value::object::tests::test_object_ptr_as_heap_storage_corrupt_magic_panics`. It expects the production magic validation panic, but `ObjectInner::validate_magic` is compiled out when neither debug assertions nor `memory-validation` is enabled. The test is not gated, so a release test with validation disabled fails although production follows its configured policy. Gate the test on `any(debug_assertions, feature = "memory-validation")` and retain the corruption assertion where validation exists. Verify `cargo test -p dotnet-value --release --no-default-features test_object_ptr_as_heap_storage_corrupt_magic_panics` and the memory-validation leg, checking discovery rather than treating a zero-match as a pass.

### LIB-24: Null sentinel test only names the constants

**Remove or strengthen** `dotnet_types::tests::test_null_exists`. It constructs `TypeDescription::NULL` and `ResolutionS::NULL` without checking either; any value assigned to those constants passes. If null sentinel semantics need a dedicated guard, assert the public null predicate and safe behavior directly; existing production and test code already compile references to both constants. Verify `cargo test -p dotnet-types test_null_exists` or the replacement selector.

### LIB-25: P/Invoke raw write-back test executes a test-only arm

**Replace** `dotnet_pinvoke::call::tests::by_ref_write_back_raw_destination_copies_bytes`. It asserts successful copy into a raw destination, but `WriteBackSource::Raw` and its copy arm exist only under `cfg(test)`; production marshaling constructs `Managed` and passes a callback to `ctx.write_bytes`. A broken production write-back can pass this test. Exercise `Managed` through the production wrapper with a recording `PInvokeContext` or a real by-ref native fixture, checking bytes, offset and error propagation; retain the existing managed-error test. Remove the test-only raw arm if no other consumer needs it. Verify `cargo test -p dotnet-pinvoke by_ref_write_back` and the applicable P/Invoke fixture.

## Reviewed families

- **Keep** `generated_runtime_slot_enum_is_in_embedded_support_assembly`, `handle_override_is_limited_to_the_support_descriptor`, `every_generated_id_and_typed_accessor_resolves_its_prescribed_owner`, `runtime_type_handle_object_ref_and_usize_views_round_trip`, `separate_span_layout_accessors_preserve_their_offsets`: loader identity and generated accessors are production paths. Synthetic layouts isolate accessor selection and offsets, and do not demonstrate actual layout generation; the embedded assembly and same-name negative control add independent connection. The ObjectRef/usize roundtrip is a view consistency check, not a standalone representation proof.
- **Keep** `generated_runtime_slot_ids_are_required`, the stub schema tests and malformed support metadata cases subject to diagnostic rewrite above. Synthetic `Resolution` directs production validator to each particular failure; these establish schema rejection, not actual C# build success. `stub_schema_rejects_duplicate_targets_without_mutating_registered_maps` checks transactional state.
- **Keep** `shared_handles_publish_and_clear_by_owner_partition` and `finalizer_queue_roots_claimed_and_pending_objects_while_worker_is_parked` in `loom_shared_tables`: production shared tables and verbatim finalizer queue are used, with real arena marking and liveness checks, owner-specific weak clearing and FIFO/completion. Rendezvous and safepoint model supply stop-the-world synchronization, so these do not validate the VM handshake; two arena threads, preemption bound 3 and 20,000 branches bound exploration. The finalizer scenario permits the worker to finish before collection; some schedules test zero live pending objects, while others test pending/active retention. Verify with the Loom command in `docs/CI.md`.
- **Keep** `fuzz_managed_ptr_roundtrip`: production write/read across unmanaged, frame-home, static, heap and cross-arena variants, unknown subtags, independent tag/checksum assertions, metadata and resolver/address checks. It primarily demonstrates internal consistency, not a complete independent wire-format oracle. Existing `signed_frame_home_serialization_and_bounds`, `frame_home_pointer_round_trips_serial_and_offset`, and `test_managed_ptr_serialization_roundtrip` add literal signed encoding, unresolved storage and live dereference checks. Inputs deliberately use live fixture objects and offsets; transient is excluded from successful decoding. Replay uses tracked nonempty corpus and verifies libFuzzer execution counts; no fuzz execution is claimed here.
- **Keep** `fuzz_raw_memory_access`: aligned live buffers, 1/2/4/8-byte atomic production loads/stores and independent width mask; skips load-invalid orderings, and the checked store/load roundtrip always uses Relaxed regardless of the selected ordering. It does not establish ordering semantics, model concurrency or exercise unaligned access. Keep replay census as an execution guard, not a quota.
- **Keep** `indirect_calls_require_explicit_sandbox_permission` and P/Invoke loader path and Linux library lifetime tests: explicit default policy, real filesystem lookup precedence and RTLD_NOLOAD observations; Linux lifetime test needs a C compiler. They do not substitute for actual FFI invocation.

- **Keep** all tests in `dotnet-metrics/src/lib.rs` test module, including the `bench-instrumentation`-gated counters, nested/out-of-order/leaked guard lifecycle and Send/Sync static assertions. They drive production metrics and compare selected literal counts, keys, percentile examples and snapshot fields; guards protect thread-local ownership, and the legacy global order is an explicit compatibility assertion. Derived lengths check completeness of declared metrics rather than imposing a test quota.
- **Keep** all seven `dotnet-tracer::tests`: filtering, backpressure conservation, flush acknowledgement, disabled lazy emission, supplied metrics and balanced drop events reach production `Tracer`/`TraceSink`; channels and finite timeouts constrain execution. Throughput test is accounting, not a speed benchmark.
- **Keep** all five `dotnet-simd::tests`: independent byte examples exercise safe and raw copy/fill/clear/equality, and vector width reports the runtime availability contract; raw operations use valid storage.
- **Keep** `dotnet-intrinsics-core::math::byte_operand_tests`: explicit signed, wide and native integer truncation cases and production min/max handlers on a real evaluation stack verify operand order, errors and remaining stack state. Hardware probes intentionally report disabled until support is complete.
- **Keep** `dotnet-intrinsics-reflection` dynamic assembly overflow and invocation window tests: production counter refuses wrapping and selection rejects specified managed-pointer operands while preserving the supplied window. Window test isolates selection and does not execute the invocation itself.
- **Keep** `dotnet-intrinsics-span::equality::tests`: chunk iteration counts verify complete bounded traversal and the multithreading-only retired-owner test verifies rejection before dereference; it directly exercises helpers, not full managed span dispatch.
- **Keep** `dotnet-intrinsics-string::simd::tests`: production optional probes are compared with scalar results, including Unicode fallback. On an unsupported host a `None` probe follows the scalar fallback, so a passing test there is not SIMD execution evidence.

- **Keep** `dotnet-intrinsics-string::operations::tests` and `substring_chunk_tests`: production asynchronous bodies are polled with a controlled backend and real GC arenas; weak roots and collection cycles verify survival through suspension and release after completion, with literal equal/unequal and UTF-16 output. Chunk counts reflect the bounded yield protocol; mock backends do not verify the executor adapter. The substring bounds cases independently check parameter ordering and invalid ranges, including overflow.

Verify with that script and `cargo test -p dotnet-vm-ops --doc`.

- **Keep** `dotnet-build-tools` path and support-slot parser tests other than the literal census discussed above. Literal fixture paths exercise the production shared build helpers for target/profile layouts and ancestor discovery. Synthetic slot records separately test documented grammar, dense IDs, uniqueness, storage/signature and view constraints; parser errors are checked by reason fragments. These do not execute MSBuild; build-script regression checks cover that integration.
- **Keep** `dotnet-vm-data::frame_alloc::tests` and `frame_homes::tests`: real production allocation ledger and nonmoving blocks exercise limits, rollback, zero-sized charge/alignment, growth, release and nested frame suspension; initialized-byte reads and live-block counters establish the F3/F10 lifetime contract, with metadata sentinels used only for movement. Home serial lookup and retirement have independent positive/negative cases. Miri runs the frame allocation family; no Miri run is claimed here.
- **Keep** `dotnet-vm-data::stack::tests`: suspension/restoration and copied slice use explicit values, while transient pointer ownership tests exercise live reads after real stack pop, peek clone, typed-ref and origin clone. Strong counts are helper-level ownership evidence; the initialized byte checks retain actual lifetime sensitivity under Miri. - **Keep** `dotnet-vm-ops::effects::tests`: the independent transition table checks valid and invalid native-control states, generations and effects against production transitions; explicit event/sleep/initializer and abandonment cases drive real effect futures. Rooted descriptor, clone, nested value and typed-reference cases use real GC and weak controls; the frame-home backend is a test adapter supplying serial lookup, not a complete VM. `raw_gc_trace_bypasses_foreign_object_recording` is multithreading-gated and checks both raw and wrapper tracing. `ops::tests::owner_retention_pointer_pops_use_trait_pop_and_reject_non_pointers` verifies default trait methods dispatch through the implemented pop and reject wrong stack types; its counter is an explicit trait-dispatch contract.

- **Keep** remaining `dotnet-runtime-memory::access::tests` and `write_barrier::tests`: production access APIs and bounded helpers test retained-owner rejection, valid and out-of-bounds access, aligned and unaligned operations, GC descriptor classification, panic guard drain and same-ID ABA rejection before callback. Panic guard tests deliberately inject buffer entries and test the guard in isolation; the live access/ABA tests reach production paths. The `dummy_wb_entry` leaks an arena deliberately to make its raw object live, and the guard tests establish buffer behavior, not actual foreign tracing. `invalid_recorder_skips_cross_arena_managed_ptrs` verifies the invalid source identity does not record a valid registered target. Cross-arena cases are multithreading-gated.

- **Keep** `dotnet-assemblies` host, loader, version, validation and drop families listed in the inventory, subject to the version setup fix. Synthetic PE and JSON inputs check concrete classification, runtimeconfig and asset paths; fixture-dependent and host CoreLib cases require built fixtures or installed runtime and several are excluded from Miri. Metadata validation uses distinct valid and malformed shapes. Weak arena handles plus actual post-loader descriptor dereference establish metadata lifetime and release; CoreLib/stub identity and retries check production loader behavior. Tests inspecting caches exercise implementation-specific caching decisions rather than guest execution.
