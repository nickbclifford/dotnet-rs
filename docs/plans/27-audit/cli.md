# CLI test audit

Baseline: `8431c1ab`. Inspection only; no tests or fault injections run. Every tracked CLI fixture and handwritten test was inspected as grouped below; findings describe limits and proposed controls, not observed test failures. `git diff --name-status 8431c1ab -- crates/dotnet-cli` returned no changes at review time.

## Discovery

Reproduce the complete tracked source inventory with `git ls-files crates/dotnet-cli`; fixture cases with `git ls-files 'crates/dotnet-cli/tests/fixtures/**/*.cs'`, debug cases with `git ls-files 'crates/dotnet-cli/tests/debug_fixtures/*.cs'`, host/F# sources with `git ls-files 'crates/dotnet-cli/tests/host_projects/*/*' 'crates/dotnet-cli/tests/fixtures_il/*'`, and handwritten Rust tests/registrations with `rg -n '#\[test\]|#\[ignore\]|(diff_test|diff_test_exit_code|multi_arena_test)!' crates/dotnet-cli/{src,tests,build.rs} -g '*.rs'`. Adjacent `cfg` and `build.rs` conditions determine active cases. There are 413 tracked regular C# fixtures, 26 debug fixtures, two F# project files and two host projects. Generated artifacts are not independent review units.

`build.rs` recursively discovers C# files, derives expected u8 exit from the filename and emits `fixture_test!`, with manually registered exceptions and two multi-arena registrations. `DOTNET_TEST_FILTER` restricts discovery. Missing DLLs become ignored except in prebuilt mode, which validates hash and rejects missing DLLs. The macro checks only `ExecutionResult.exit_code`, after the in-process executor maps `Exited` to guest code, `Threw` to 254 and host setup/execution errors to 255. Feature-specific ignores and the observed-error fuzzing return affect interpretation. Differential tests invoke actual CLI and CLR, compare exit and stdout (except three exit-only cases), and time out both processes; they are excluded in fuzzing, and some are MT, Unix, Linux or debug gated. The F# reflection-tail case builds and parses emitted IL. Path events are forwarded to a scoped receiver on the emitting thread, not all worker threads. See `docs/CI.md` for runner interpretation.

## Findings for 27b

**CLI-1 — Rewrite — generated stack-trace tests do not check stack traces.** `exceptions_stack_trace_no_params_254`, `exceptions_stack_trace_params_254`, `exceptions_stack_trace_generic_254` throw but never inspect a trace; `fixture_test!` accepts any `ExecutorResult::Threw` as 254. An incorrect exception or missing method names, parameters or generic frames passes. Their names and inputs establish the intended distinction; an unhandled-exception smoke alone remains useful. Retain that smoke and assert exception identity and selected frame/method properties through the observable stack-trace path, allowing noncontractual formatting differences; use CLR comparison where supported. Verify `cargo nextest run -p dotnet-cli --test integration_tests -E 'test(stack_trace)'` and the unhandled exception case. Inspection conclusion, not a demonstrated runtime bug.

**CLI-2 — Rewrite — `multicast_selection_precedes_operand_commitment` and `reflection_path_selection` bind guest scenarios to instrumentation cardinality.** Production emits `multicast_path = "async"` immediately before `start_native`; an event reports selection, not correct ordering of operand commitment. Exact fixture counts and source exclusions for `multicast_path = "fallback"` and `multicast_state` reject correct restructuring, renaming or instrumentation changes; an incorrectly placed event could satisfy counts while an unexercised ordering defect persists. Reflection's exact tuples similarly tie behavior to event count and ignore unknown event values. Retain concrete guest outcomes and CLR comparisons for invocation, aliasing, exceptions, GC and re-entry. Replace the ordering claim with a scenario that observably distinguishes premature commitment, and keep a narrow path test only if asynchronous selection itself is an explicit internal requirement. Verify named tests plus delegate/reflection differential fixtures under default and no-default features. All named multicast fixture bodies are covered by the delegate batch below.

**CLI-3 — Rewrite — fuzzing `fixture_test!` reports some failures as passing tests.** On mismatched exit it returns successfully for broad `EntryPointNotFoundException` or `TypeInitializationException` plus `SystemNative_`, or merely TimerQueue initializer text. An unrelated initializer error containing that text can count as pass, and a dynamically skipped test defeats CI's unexpected-ignore accounting. Fuzzing intentionally denies P/Invoke; classify unsupported native cases explicitly and surface skips/ignores, while unexpected managed/host failures fail; retain non-native execution. Derive exclusion from reviewed cases or structured denial, and make CI expected-ignore accounting cover it. Verify `cargo nextest run -p dotnet-cli --test integration_tests --features fuzzing` with denied and non-denied cases and an unrelated TimerQueue failure control. No fault injection performed.

**CLI-4 — Merge/remove misleading feature smoke assertions — `test_single_threaded_sync_block_manager`, `test_multithreading_sync_blocks`, `test_multithreading_gc_coordinator_exists`.** Field references cannot test synchronization or GC coordination; registering a thread does not operate a sync block. A broken lock still passes. Field access is compile-time evidence already required by compilation. Remove or rename as compile smoke; if intended as synchronization evidence, retain or add real lock/ownership behavior in the production subsystem. `test_multithreading_arena_handle` asserts only no panic, not registry contents. Verify `cargo nextest run -p dotnet-cli --test feature_config_tests` and with `--no-default-features`.

## Interpretation

Differential macros use `from_utf8_lossy` for stdout and convert missing process code to 255 then `u8`; distinct invalid byte sequences can compare equal. The three exit-only cases expect 7 or 42, so a signal cannot satisfy them. Prefer byte equality and explicit status handling for binary stdout or 255 differential cases; confirm all registrations before treating this as a current failure. `exceptions_intrinsic_trace_42_matches_dotnet_exit_code` intentionally cannot detect its documented CLR/VM stdout divergence. `exceptions_exception_filter_7_matches_dotnet` and `exceptions_filter_throws_keeps_original_matches_dotnet` use meaningful fixture-derived state and identity checks.

Commands above have not been run. The host project manual differential route is `scripts/diff_run.sh --host`, with `DOTNET_RS_BIN` set to the CLI; it compares exit and stdout, not successful DI background compilation.
