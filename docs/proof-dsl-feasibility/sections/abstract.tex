\noindent \dotnetrs{} contains 581 \code{unsafe} blocks whose
soundness rests on 620 prose \safetyc{} comments. This study evaluates
a proposal to replace trust in that prose with machine-checked proof:
a dependently-typed, Curry--Howard-style DSL in which each comment's
argument becomes a checkable term. Drawing on a survey of the
repository's unsafe corpus (which factors into approximately nine
invariant families and 40--60 sites of genuine difficulty), the Rust
verification literature (RustBelt, RefinedRust, VeriFast, Verus, Tree
Borrows, RFC 3842 safety tags), and the state of managed-runtime
formalization (no mechanized ECMA-335 model exists), we find the
proposal feasible for a single developer with LLM-agent support, under
one architectural correction: the DSL should be untrusted surface
syntax elaborated into Lean~4 rather than a language with its own
kernel. The recommended design is an embedded, tactic-oriented
proof-script language in the lineage of \code{dotnetdll}'s \code{asm!}
macro --- block-shaped scripts wrapping each \code{unsafe} site, whose
premises are zero-sized ghost tokens checked by \code{rustc} for
existence, \code{cfg}-liveness, and dataflow --- elaborating
deterministically to statements over an executable Lean model of the
ECMA-335 core, differentially tested against the project's fixture
oracle, paired with a small Miri-falsifiable axiomatization of Rust's
memory model. The verifier decomposes into independently versioned
packages whose only contact with the VM is two build dependencies and
two content-hashed manifest artifacts, so ordinary builds never invoke
Lean. Two soundness defects introduced into the codebase shortly
before this study --- both instances of prose citing a witness that no
code establishes --- supply the empirical premise; under the token
design one of them is not expressible. Both defects, and the rest of
this study's proposed Phase 0, were fixed by ordinary review before
this revision. We give a staged roadmap
(hygiene, embedded token layer, VES model, protocol theorem, site
campaign) together with a decomposition into supervised agent-refactor
work packages sized by checklist complexity and verification-signal
quality; every stage terminates in an independently usable artifact,
and the mechanized ECMA-335 core is publishable regardless of the
proof campaign it enables.
