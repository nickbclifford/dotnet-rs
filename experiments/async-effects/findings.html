1. Verdict

Feasible on stable Rust, no nightly features. The 2026-07-03 walls are real, but they only rule out one design: a future that holds a Gc<'gc> across an .await. If GC access is instead confined to short scoped regions, .await points become effects and the executor becomes their handler. That is the monadic-effects reading made concrete. The borrow checker enforces the key soundness rule, and Miri (tree-borrows) is clean.

The type-theoretic framing: each cx.with(…) is a runST-style region whose for<'gc> brand cannot escape. Stashing is the explicit lift of a value across an effect boundary. Each .await performs one operation, and the driver loop interprets it.

2. What the July investigation got right — and what it ruled out

Both walls from 2026-07-03 still stand:

  1. 'gc cannot escape Arena::mutate. The closure is for<'gc> FnOnce(&'gc Mutation<'gc>, …), so a future branded 'gc can't be stored where collections happen.
  2. An async fn state machine can't impl Collect. Any Gc it holds across .await would be untraced, then freed, then dangling.
// What July tried — and what genuinely cannot work:
async fn intrinsic<'gc>(ctx: &mut VesContext<'gc>, s: ObjectRef<'gc>) {
    let chars = s.borrow();       // Gc<'gc> live…
    safepoint().await;            // …across a point where the collector may run
    use_it(chars);                // untraced: the async state machine can't impl Collect
}

The conclusion drawn at the time, “drop the async framing entirely”, went too far. Neither wall applies to a future that never holds a Gc, as long as it can still reach the heap whenever it is not suspended.

3. The design: regions, stashes, effects

PieceRole
'static future, outside the arenaThe effectful computation. It never holds a Gc.
cx.with(|mc, engine| …)A GC region, a thin wrapper over mutate_root. Nothing 'gc-branded can be returned from it.
Stashed / DynamicRootThe only way a GC reference crosses an .await. Traced from the root.
cx.safepoint().await, cx.call_managed(m, args).awaitEffect operations. Each records an Effect in a side channel and returns Pending.
Vm::runThe handler. On SafePoint it runs a full GC. On AwaitManagedReturn it resumes the interpreter until the callee frame returns.

3.1 The region

/// A task's capability to touch the VM. Cheap to clone; `'static`.
#[derive(Clone)]
pub struct Cx(Rc<Shared>);

impl Cx {
    /// Enter a GC region. The closure is `for<'gc>`, so its return type `T`
    /// cannot mention `'gc` — nothing GC-branded can reach an `.await`.
    pub fn with<T>(
        &self,
        f: impl for<'gc> FnOnce(&'gc Mutation<'gc>, &'gc mut Engine<'gc>) -> T,
    ) -> T {
        self.0
            .arena
            .try_borrow_mut()
            .expect("Cx::with re-entered (nested GC regions are not allowed)")
            .mutate_root(f)
    }
}

This fails to compile, which is the point (it is a compile_fail doctest in the crate):

async fn bad(cx: Cx) {
    let held = cx.with(|_, e| e.stack[0]); // Value<'gc> escaping the region
    cx.safepoint().await;
    let _ = held;
}
error: lifetime may not live long enough
  = note: requirement occurs because of the type `Value<'_>`, which makes the generic argument `'_` invariant
  = note: the enum `Value<'gc>` is invariant over the parameter `'gc`

I extracted the doctest and compiled it by hand to confirm it fails for this reason, not an incidental one. The guard also caught a real slip while I wrote the benchmark: cx.with(|_, e| e.stack.pop()) was rejected because it returned an Option<Value<'gc>>.

The sanctioned version stashes first:

async fn good(cx: Cx) {
    let held = cx.with(|mc, e| Stashed::stash(e.stack[0], mc, &e.roots)); // 'static handle
    cx.safepoint().await;                                                 // GC may run here
    cx.with(|_, e| { let _v = held.fetch(&e.roots); });                   // re-brand inside a region
}

3.2 Stashing

/// The `'static` mirror of `Value<'gc>`: what a task may hold across `.await`.
#[derive(Clone)]
pub enum Stashed {
    Int(i64),
    Arr(DynamicRoot<Rootable![RefLock<Vec<i64>>]>),
}

impl Stashed {
    pub fn stash<'gc>(v: Value<'gc>, mc: &Mutation<'gc>, roots: &DynamicRootSet<'gc>) -> Self {
        match v {
            Value::Int(i) => Stashed::Int(i),
            Value::Arr(a) => Stashed::Arr(roots.stash::<Rootable![RefLock<Vec<i64>>]>(mc, a)),
        }
    }
    pub fn fetch<'gc>(&self, roots: &DynamicRootSet<'gc>) -> Value<'gc> {
        match self {
            Stashed::Int(i) => Value::Int(*i),
            Stashed::Arr(a) => Value::Arr(roots.fetch(a)),
        }
    }
}

Plain data (integers, here) needs no rooting. Only GC references pay for a root-set slot. Since 0.6, DynamicRootSet stores roots in slots with no per-root allocation.

3.3 Effects and the handler

/// What a suspended task is waiting on. The driver is the handler.
pub enum Effect {
    /// Let the collector run, then resume me.
    SafePoint,
    /// I pushed a managed frame; resume me when it returns (value in `task_reply`).
    AwaitManagedReturn,
}

impl Future for Perform {
    type Output = ();
    fn poll(mut self: Pin<&mut Self>, _: &mut Context<'_>) -> Poll<()> {
        match self.effect.take() {
            Some(e) => { self.cx.0.effect.borrow_mut().replace(e); Poll::Pending }
            None => Poll::Ready(()),
        }
    }
}

impl Cx {
    pub fn safepoint(&self) -> Perform { self.perform(Effect::SafePoint) }

    /// Call a managed method and await its return value — straight-line, from Rust.
    pub async fn call_managed(&self, method: usize, args: &[Stashed]) -> Stashed {
        self.with(|_, e| {
            let base = e.stack.len();
            for a in args { e.stack.push(a.fetch(&e.roots)); }
            e.frames.push(Frame { method, ip: 0, base, ret: ReturnTo::Task });
        });
        self.perform(Effect::AwaitManagedReturn).await;
        self.with(|mc, e| {
            let v = e.task_reply.take().expect("resumed without a reply");
            Stashed::stash(v, mc, &e.roots)
        })
    }
}
pub fn run(&mut self) -> Vec<String> {
    loop {
        // 1. Resume the innermost task, if any, and handle the effect it performed.
        if let Some(task) = self.tasks.last_mut() {
            match task.as_mut().poll(&mut Context::from_waker(Waker::noop())) {
                Poll::Ready(v) => {
                    self.tasks.pop();
                    self.cx.with(|_, e| { let v = v.fetch(&e.roots); e.stack.push(v); });
                }
                Poll::Pending => match self.cx.0.effect.borrow_mut().take().unwrap() {
                    Effect::SafePoint => { self.full_gc(); continue; }   // re-poll same task
                    Effect::AwaitManagedReturn => {}                      // fall into interpreter
                },
            }
        }
        // 2. Run the synchronous interpreter until something needs a task.
        loop {
            match self.cx.with(|mc, e| e.step(mc)) {
                Step::Continue => {}
                Step::Spawn(i, args) => { self.tasks.push(spawn(self.cx.clone(), i, args)); break; }
                Step::TaskReply => break,
                Step::Done => return self.cx.with(|_, e| std::mem::take(&mut e.output)),
            }
        }
    }
}

The hot dispatch step (Engine::step) is ordinary synchronous code and never polls a future. Tasks form a stack parallel to the frame stack: a task can call managed code, and that code can start another task.

4. What intrinsics look like

Notice what is absent: no back_up_ip, no retry flag, no continuation enum variant, no re-deriving progress after a yield.

Chunked work with safe points

async fn chunked_sum(cx: Cx, arr: ArrRoot) -> Stashed {
    let len = cx.with(|_, e| e.roots.fetch(&arr).borrow().len());
    let (mut off, mut acc) = (0, 0i64);
    while off < len {
        let end = (off + CHUNK).min(len);
        acc += cx.with(|_, e| e.roots.fetch(&arr).borrow()[off..end].iter().sum::<i64>());
        off = end;
        cx.safepoint().await;   // `off` and `acc` survive the collection
    }
    Stashed::Int(acc)
}

Calling back into managed code, straight-line

async fn sort_with(cx: Cx, arr: ArrRoot, comparer: usize) -> Stashed {
    let len = cx.with(|_, e| e.roots.fetch(&arr).borrow().len());
    for i in 1..len {
        let mut j = i;
        while j > 0 {
            let (a, b) = cx.with(|_, e| {
                let v = e.roots.fetch(&arr);
                let v = v.borrow();
                (v[j - 1], v[j])
            });
            // a managed method runs here — the interpreter resumes, then returns to us
            let c = cx.call_managed(comparer, &[Stashed::Int(a), Stashed::Int(b)]).await;
            if c.int() <= 0 { break; }
            cx.with(|mc, e| e.roots.fetch(&arr).borrow_mut(mc).swap(j - 1, j));
            j -= 1;
        }
    }
    Stashed::Arr(arr)
}

6. Prior art: piccolo already does this

The July memo cited piccolo (kyren's Lua VM on gc-arena) as evidence that hand-written Collect Sequences were the idiomatic answer, not async. piccolo's master branch has since added src/async_callback.rs (2024; not in any crates.io release, since 0.3.3 lacks it). Its own Sequences are now implemented by async blocks:

// kyren/piccolo master, src/async_callback.rs (2024, unreleased)
pub fn async_sequence<'gc, F>(
    mc: &Mutation<'gc>,
    create: impl FnOnce(Locals<'gc, '_>, AsyncSequence) -> F,
) -> BoxSequence<'gc>
where
    F: Future<Output = Result<SequenceReturn, StashedError>> + 'static,

impl AsyncSequence {
    pub fn enter<F, R>(&mut self, f: F) -> R
    where
        F: for<'gc> FnOnce(Context<'gc>, Locals<'gc, '_>, Execution<'gc, '_>, Stack<'gc, '_>) -> R,
}
“Can be used to implement Sequence in a way MUCH easier than manual state machines. … The returned future … cannot capture anything branded with a 'gc lifetime … This is the reason why we provide a Locals: to instead allow the future to hold onto these GC values indirectly.” — piccolo docs

Two differences from the prototype

This prototypepiccolo
Where the future is polledOutside mutate; the arena sits in a RefCellInside mutate; the future is wrapped in a Collect BoxSequence in the GC graph
How regions get the contextmutate_root per regionA lifetime-erased shared slot (~2 unsafe transmutes)
unsafenonesmall, contained
Root setOne global DynamicRootSet on the engineOne per sequence (Locals), traced through the sequence, so abandoned sequences and cycles are collected

The global root set is acceptable for dotnet-rs, because a suspended .NET native frame is never garbage while its thread lives. Per-task sets still give cleaner teardown on thread exit or abort.

Recommendation: piccolo's approach for dotnet-rs. A task can live in the root as something like VmContinuation::Task(..), which subsumes the Tier-1 continuation type. An intrinsic can start and poll its task inside the same mutate, so a task that never suspends costs almost nothing. Executor::run and with_arena don't have to change. The cost is two small unsafe blocks, which fit the existing SAFETY-citation (F-code) discipline.

7. What it buys dotnet-rs

7.1 Chunked intrinsics stop restarting from zero

// crates/dotnet-intrinsics-string/src/search.rs (today)
let mut result_vec = Vec::with_capacity(l);
let mut offset = 0;
while offset < l {
    /* … copy one 64K-char chunk under a GcScopeGuard … */
    offset += current_chunk;
    if offset < l && ctx.check_gc_safe_point() {
        return StepResult::Yield;   // result_vec and offset are discarded;
    }                               // back_up_ip() re-runs the instruction from offset 0
}

Under sustained GC-stop pressure, a long string operation redoes its copied prefix on every retry. With safepoint().await, progress survives the yield, as in chunked_sum. Sites: dotnet-intrinsics-string/src/search.rs:135,259 and the similar chunked loops in operations.rs, constructors.rs, span equality.rs, and unsafe buffer.rs/mem_helpers.rs. About 51 Yield/should_yield sites in total.

7.2 The Tier-1 residue

  • GC.WaitForPendingFinalizers (dotnet-vm/src/intrinsics/gc.rs:199) currently “effectively spins until finalizers complete”.
  • The static-init wait (dotnet-vm/src/statics.rs:476) returns a bare should_yield bool.

Both become an .await on a condition effect.

7.3 Managed re-entry

FrameReturnAction::InvokeReturn (reflection invoke) and MulticastState (multicast delegate invoke) are hand-written “call managed code, then continue” state machines. That is exactly what call_managed(..).await expresses directly.

8. Open problems (not prototyped)

  • Exceptions through a task boundary. The unwinder must stop at a ReturnTo::Task frame and deliver Err to the task. call_managed should return Result, and the task propagates with ?. Stack traces need a synthetic native frame.
  • Multithreading. The SafePoint handler must take part in the stop-the-world handshake (thread_manager.safe_point(..) / GCCoordinator). Stashing a cross-arena reference into a per-thread DynamicRootSet is unverified.
  • Discipline the compiler doesn't check. Awaiting anything other than a Cx effect panics at runtime (“Pending without an effect”), and so does nesting with calls. piccolo has the same limitation.
  • Observability. Task state is opaque to the tracer and the instruction ring buffer.
  • !Send futures. Fine as long as tasks never migrate between executor threads, which matches the current thread-affine design.

9. gc-arena 0.7.0 (August 2026)

Orthogonal to this design; the prototype passes on it unchanged. It matters to dotnet-rs for other reasons:

  • Gc now points to T directly. This removes the 0.6.1 soundness requirement that Gc::cast / Gc::from_ptr source and target share alignment. dotnet-rs has 4 such call sites, in dotnet-runtime-memory/src/heap.rs and dotnet-value/src/object/mod.rs. That is relevant to the pointer-provenance work.
  • Pacing counts Gc pointers, not bytes. Any tuned pacing factors (and the VM's allocation-pressure heuristics) would need revisiting. The Metrics::total_gc_allocation API changed too.
  • New ZstCache for sharing one allocation among Gcs to zero-sized types.

10. Recommended next step

A narrow vertical slice inside the real VM, using piccolo's approach:

  1. Add a Collect task wrapper plus a per-task DynamicRootSet, stored as a VmContinuation variant on ThreadContext.
  2. Add StepResult-level plumbing for “task suspended on effect X”, handled in Executor::run.
  3. Port one chunked string intrinsic (search.rs) to safepoint().await, and add a test proving progress is kept under forced GC-stop requests.
  4. Only then attempt call_managed with exception propagation, which is the real design risk.
